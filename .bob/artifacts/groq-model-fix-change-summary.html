Groq Model Fix — Change Summary

smart-onboarding-assistant · Session recap · 3 iterations

What Was the Issue

Root Cause

The Groq API was returning a 500 Internal Server Error on every POST /api/v1/onboarding/generate-docs request with the message:

"The model `llama-3.1-8b-instant` does not exist or you do not have access to it."

The model name configured in the project did not match any active, accessible model on Groq's API for the provided API key. This caused every documentation generation request to fail immediately.

Why It Kept Recurring

The fix was applied to app/config.py (the Python default) but the .env file always overrides Python defaults at runtime via Pydantic Settings. Since .env still had the old value, the server kept using the bad model name — making the config.py fix invisible until .env was also corrected.

Fix Iterations

  • 1
    Iteration 1 — Fixed app/config.py default from llama-3.1-8b-instant to llama3-8b-8192. Issue persisted because .env still overrode it.
  • 2
    Iteration 2 — Discovered .env (copied from .env.example) still had the old value. Fixed both .env and .env.example to llama3-8b-8192. However, llama3-8b-8192 itself was subsequently decommissioned by Groq.
  • 3
    Iteration 3 — Queried Groq's live /models endpoint and tested all candidate models against the actual API key. Found all Llama / Mixtral / Gemma models were either decommissioned or inaccessible. Updated all three files to the confirmed-working model openai/gpt-oss-20b.

Key Lesson

Important

When using Pydantic Settings, .env always wins over Python defaults. Fixing only config.py has zero effect at runtime if the same variable exists in .env. Always update both .env and .env.example together to keep them in sync.
